# 命学真典

把一本命理书籍拆解成若干个可被 AI 直接调用的八字分析技能包。

产出的不是读书笔记，不是摘要，是**一套建立在四柱八字模型之上的断法规则系统**——给定一个八字排盘，AI 能沿模型的节点路径，把书中所有适配规则一次性检索出来，形成分析结论。

## 与原版的核心差异

| 维度 | 通用版 | 命理版 |
|------|--------|--------|
| 组织框架 | 无预设模型 | 四柱八字模型（`bazi-model.md`） |
| 提取轨道 | 框架/原则/案例/反例/术语 | 规则断法/命例/格局/误区/术语 |
| 规则归并 | 按用户场景 | 按模型节点 + 用户场景 |
| 输出形态 | 通用操作指令 | 沿模型路径分层的规则索引 + 可检索命例库 |
| 验证重点 | 原文支撑/预测力/常识 | 模型一致性/规则冲突检测/命例佐证 |

## 执行总则

- 全自动执行。除了第 0 步的闸门，中途不向用户提问
- 这是长任务，开启多 Agent 并行能力
- 每完成一步，立即把进度写入 `状态.md`（第 3 步有特殊的落盘顺序要求）
- 每一步开始和结束向用户播报一行进度，**带上工作目录路径**
- 全程用中文交流
- 内容包含违法操作或伤害他人的具体方法，立即停止并说明原因

本技能自带的参考文件，用到时才读：

| 文件 | 什么时候读 |
| --- | --- |
| `references/bazi-model.md` | 第 1 步生成模型索引画布时、第 3 步派发子 Agent 时 |
| `references/skeleton-template.md` | 第 2 步写骨架前 |
| `references/skill-template.md` | 第 5 步构造技能包前 |
| `references/extractor-bazi-rule.md` | 第 3 步派发子 Agent |
| `references/extractor-bazi-case.md` | 第 3 步派发子 Agent |
| `references/extractor-bazi-pattern.md` | 第 3 步派发子 Agent |
| `references/extractor-counterexample.md` | 第 3 步派发子 Agent |

## 第 0 步 · 闸门检查

任何一道没过，立即停止，用**大白话**告诉用户原因和他该怎么办。

### 闸门一 · 文件在不在

用户还没提供文件，就停下来告诉他：请把要蒸馏的命理书发给我，支持 txt、md、docx、pdf、转写稿。然后等待。

### 闸门二 · 文字读不读得出来

抽取文件的开头、中间、结尾各约 500 字，检查是否为空白、乱码、或全是无意义符号。

读不出文字：
> 你发的这个文件是扫描件，里面是图片不是文字，我读不出内容。你需要先用文字识别工具把它转成可复制的文字版，再发给我。

格式打不开：
> 这个格式我这边打不开。你把它另存成 txt 或者 Word 文档再发我一次就行。

### 闸门三 · 这份命理内容适不适合蒸馏

这一关比其他任何类型都重要。命理书有三种需要拦截的情况：

| 类型 | 判断依据 | 处理 |
|------|----------|------|
| 排盘工具书 | 只讲怎么起八字、排大运、算神煞，没有断法逻辑 | 停止 |
| 命理故事书 | 用八字讲名人故事，但没有可提取的断法规则 | 停止 |
| 基础教材 | 只讲十神定义、五行生克这些入门概念，没有作者自己的断法 | 停止 |
| 断法书 | 有具体的"X 配置 → Y 结论"式规则，有命例佐证 | **继续** |

判断方法：随机翻三段，问自己"这段话里有没有一条能从八字配置推出人生结论的规则"。三段都没有，就是不适合。

**注意区分**：排盘部分即使占了很大篇幅也不计入有效内容，真正的有效字数只算断法论述 + 命例分析部分。按这个口径算，体量少于 5,000 字停止。

> 这份内容我读了，它主要是讲排盘/基础概念/故事，里面没有可以拆成断法规则的东西。命理书的蒸馏需要的是"这个配置出这个结果"的判断逻辑，不是操作步骤或基础概念。

### 闸门四 · 多文件分流

逻辑同原版闸门四，但额外加一条：合并蒸馏的前提是所有文件属于**同一命理流派或同一作者**。流派不同的不能合蒸（旺衰派和盲派的断法体系互相矛盾，混在一起产出的技能包会自相矛盾）。

### 闸门都过了

> 检查通过。这份命理内容约 X 万字，我判断适合蒸馏。命理蒸馏会先把书中的断法规则全部提取、逐条挂载到四柱八字模型上，再按模型节点组织成技能包。这个过程会跑一段时间。
>
> 中途你随时可以打断。同一个对话里，跟我说"继续"就行。如果你关掉对话重新开一个，就说：**继续蒸馏，目录在 <工作目录完整路径>**。
>
> 现在开始。

## 第 1 步 · 建立工作区

在用户的工作目录下新建文件夹 `蒸馏_<内容标题>`。

内容标题取自封面、首页或文件名。

| 路径 | 用途 |
| --- | --- |
| `原文/` | 输入文件的纯文本分块 |
| `候选/` | 提取出的原始候选（五路产出） |
| `候选/bazi-index.md` | **四柱八字模型画布**——把 `references/bazi-model.md` 复制过来作为规则挂载的索引画布 |
| `技能包/` | 最终产物，里面只放技能文件夹 |
| `状态.md` | 进度记录 |

### 切块

**先剔除非正文部分**：封面、版权页、目录、前言致谢、参考文献、附录里的万年历/排盘表。

**剔除只针对切块和提取。** 第 2 步做骨架时，目录和前言照样读。

剔除后剩下的才是**有效字数**。

然后切块：

- 块大小 = 有效字数 ÷ 20，限制在 2,000 到 10,000 字之间
- 书按章切；一章超过块大小就沿小节边界往下切
- **不要在句子或段落中间切断**
- 给每块连续编号，从 1 开始。**总块数是后面覆盖率检查的依据**

批大小固定为 5 块，批数 = 总块数 ÷ 5 向上取整。

### 生成模型索引画布

把 `references/bazi-model.md` 的 **L1-L3 不可变底层**（四柱、十神、五行）复制到 `候选/bazi-index.md`。L4-L8 区域留空，标注 `[待第 2 步骨架生成]`。

骨架产出后，把骨架中的"书专属模型扩展（L4-L8）"追加到 `候选/bazi-index.md`，形成完整的书专属模型树。

### 图表依赖度检查

命理书常有排盘表、干支对照图。检查"如图""见表""如下排盘"这类引用。图表不可见时，在 `状态.md` 记一笔，并在第 3 步派发时告诉子 Agent：遇到排盘图表不可见时，从前后文把八字排盘信息重建出来；重建不出来就不记录。

### 写状态

`状态.md` 记录：内容标题、输入类型、有效字数、总块数、批数、目标技能包数量、当前进度。多文件合并蒸馏时额外记录每个文件的原始文件名和流派判定。

文件开头加一行：

> 如果你是新会话，请先加载「命学真典」技能，再按下面记录的进度接着执行。

## 第 2 步 · 全局骨架与模型热度

由你自己完成，不派子 Agent。先读 `references/skeleton-template.md`。

通读目录、每章开头结尾、以及随机抽取的若干块，按模板产出 `骨架.md`。

命理版的骨架有三项特殊内容必须写透，另产出一项关键参数：

1. **书专属模型扩展**：从本书章节目录中生成 L4-L8 的完整模型树。bazi-model.md 只提供 L1-L3 不可变底层和词汇参考卡片，L4-L8 由你根据本书的实际结构创建。这是第 3 步所有提取器的分类体系，也是第 4 步模型一致性校验的基准。**注意：目录中的通用断法章（论性情/论疾病/论大运/论太岁/纳音）必须如实长成节点并标热度——第 5 步有规则专门承接这类跨格局内容。**
2. **结构主干**：判断本书是格局型/断事型/概念型/调候型/混合型中的哪一种。这直接决定第 5 步技能包的归并方向。判断错了，产出的技能会在错误的维度上切割规则。
3. **作者的断法风格**：明确指出本书的流派倾向和推理路径偏好，这是第 4 步规则冲突检测的基准。
4. **内容简称**：从书名中提取 2-4 个字的拼音简称（如渊海子平→`yaunhai`、子平真诠→`ziping`、滴天髓→`ditiansui`、穷通宝鉴→`qiongtong`）。这个简称将在第 5 步作为所有技能 name 的**强制前缀**，防止蒸馏多本书时撞名。

盲点与边界至少写满 3 条。写完做骨架自检：随机抽 3 个块，逐一检查骨架能不能解释它们。有一个解释不通就重写一次，只重写一次。

## 第 3 步 · 五路分批并行提取

### 五路轨道

原始通用版的框架/原则两路在命理蒸馏中被合并，因为命理书没有独立的"框架"概念——命理框架就是格局体系。命理版五路如下：

| 子 Agent | 提取器文件 | 输出 |
| --- | --- | --- |
| 规则 | `references/extractor-bazi-rule.md` | `候选/规则.md` |
| 命例 | `references/extractor-bazi-case.md` | `候选/命例.md` |
| 格局 | `references/extractor-bazi-pattern.md` | `候选/格局.md` |
| 误区 | `references/extractor-counterexample.md` | `候选/误区.md` |
| 术语 | `references/extractor-glossary.md` | `候选/术语.md` |

### 执行方式

按批次循环，每批之内五路并行，批与批之间顺序执行。

对第 1 批到最后一批，依次：

1. 同时启动五个子 Agent
2. 五路都返回后，做覆盖率检查
3. 结果追加到上表对应的候选文件
4. 候选**全部落盘之后**，再更新 `状态.md`
5. 播报：已完成第 X 批，共 Y 批
6. 进入下一批

并行度始终是 5。

### 派发时必须传给每个子 Agent 的信息

1. 它的提取器文件的完整路径
2. **`候选/bazi-index.md` 的完整路径**——此文件包含 L1-L3 不可变底层 + 骨架生成的 L4-L8 书专属模型树（第 2 步完成后已追加）。子 Agent 以此为唯一分类体系标注规则/命例的模型路径
3. **骨架热度表**——摘自 `骨架.md` 的"书专属模型扩展"：🔥🔥🔥/🔥🔥 的节点列为**优先提取**，🔥/✗ 的节点列为**可跳过**。子 Agent 不要在 ✗ 节点上浪费提取资源
4. 本批包含哪几块，以及这几块的完整文件路径
5. 它必须逐块处理，一块都不能跳
6. 输出文件的完整路径
7. 必须给出逐块回执

### 覆盖率检查

检查每一路的**逐块回执**。只要有一块没有回执，就把那一路针对本批重派一次，只让它补漏掉的那几块。重派最多一次，第二次仍不完整就接受现状，在 `状态.md` 记下来。

### 降级路径

环境不支持多 Agent 并行，就顺序执行五路，事前告诉用户。

## 第 4 步 · 验证与模型一致性校验

### 四层验证（不同于原版的三重验证）

命理蒸馏的验证维度和通用版不同：

### 验证一 · 原文支撑

每条规则/格局/反例必须能定位到原文具体位置，附一句原文摘录。定位不到原文的，淘汰。

| 输入类型 | 佐证标准 |
| --- | --- |
| 书 | 至少在原文中有 1 处明确论述或 1 个命例佐证即可；命理经典常将元规则定义一次、全书沿用而不再重申，不应因此淘汰 |
| 转写稿 | 在不同话题段被复用，或讲者在追问下二次展开 |

### 验证二 · 模型路径完整

每条规则必须标注了至少一条在 `候选/bazi-index.md` 中的模型路径。没有模型路径的规则，补标后重审；补不上的淘汰。

### 验证三 · 规则一致性

对同一模型节点的多条规则，逐条比对：
- 多条规则指向同一结论 → 合并为一条，标注"多源验证"
- 多条规则结论相反 → 标记冲突，写入 `候选/冲突记录.md`，由你根据骨架中的"作者断法风格"判断哪条是作者的真正主张、哪条可能是行文矛盾或上下文特例。判断不了的标记为"待用户裁决"
- 某条规则和其他所有规则都矛盾 → 可能是误提取或上下文过度推断，降低置信度

### 验证四 · 命例-规则交叉验证

把命例提取器产出的命例和规则提取器产出的规则做交叉校验：

- 命例的"涉及规则"列表中引用了哪些规则，反过来检查这些规则是否真的在候选/规则中存在
- 规则如果声称适用于某种配置，检查命例库中是否有对应配置的命例佐证
- 命例的"推理链"如果和对应规则的断法步骤不一致，标记为"推理链与规则不一致"

**报告区分**：交叉验证结果写入 `清单.md` 时，必须区分书种：
- 理论型书（如子平真诠）命例少是常态。低覆盖率不标为质量问题，只客观报数，附带一句"本书为理论型，规则以逻辑推导为主，命例佐证比例天然偏低"
- 案例型书命例多。低覆盖率应标为问题并说明可能原因

### 自动纠偏

统计规则通过率（分母只算规则提取器产出）：

| 输入类型 | 正常范围 | 过高线 | 过低线 |
| --- | --- | --- | --- |
| 命理书 | 25% 到 45% | 高于 60% | 低于 8% |
| 转写稿 | 10% 到 25% | 高于 40% | 低于 5% |

- 高于过高线 → 验证二（模型路径）放水了，收紧路径完整性要求，重筛一次
- 低于过低线 → 验证一（原文支撑）卡太死，放宽佐证判据，重筛一次
- **只重筛一次**

### 全军覆没的处理

重筛后通过数仍然是 0：

> 我把这份命理内容里的候选都验了一遍，没有一条能同时满足"有原文支撑""能挂到模型上""与其他规则一致"这三条。我把提取到的原始候选放在 `候选/` 目录里了，你可以自己看看有没有想留的。

然后停止。

淘汰条目写入 `候选/淘汰记录.md`。

## 第 5 步 · 构造技能包

先读 `references/skill-template.md`。

### 归并逻辑

归并方向由骨架中的**结构主干**决定，不再硬编码优先级：

---

**当 结构主干 = 格局型 时：按格局分组，每个格局一个技能。**

以子平真诠评注为例：产出的技能是 `mingli-zhengguan-ge`（正官格）、`mingli-qisha-ge`（七杀格）、`mingli-cai-ge`（财格）等。每个技能内部按"成格破格 → 用神相神 → 行运宜忌 → 按断事分层（婚姻/事业/财运/健康）"组织。

用户问"这个八字的婚姻"→ 技能内部先判格局 → 再取该格局的婚姻规则。无需用户先跑一个取格技能再跑一个断事技能——格局判定逻辑作为技能的第一步内置。

**当 结构主干 = 断事型 时：按断事分组，每个断事领域一个技能。**

以现代案例书为例：产出 `mingli-hunyin`、`mingli-shiye`、`mingli-caiyun` 等。每个技能内部按格局分层（正官格婚姻→七杀格婚姻→...），让用户直接按问题领域触发。

**当 结构主干 = 概念型 时：按核心概念分组，每个概念一个技能。**

以滴天髓为例：产出 `mingli-tiyong-lun`（体用论）、`mingli-shuaiwang-lun`（衰旺论）、`mingli-tongguan-lun`（通关论）等。每个技能内部是"概念阐释 → 任铁樵注疏命例 → 此概念的断事应用（对婚姻/事业/财运各意味着什么）"。六亲论的内容作为关联命例挂入，或按断事维度在概念技能内设子节。

**当 结构主干 = 调候型 时：按月份分组。**

以穷通宝鉴为例：12 个月各一个技能（`mingli-zhengyue-tiaohou` → `mingli-shieryue-tiaohou`）。若有效字数 <30,000，合并为四季（`mingli-chunji-tiaohou` 等，每季含 3 个月 × 10 日干 = 30 格）。每个技能内部按日干分层列出各格的调候口诀、喜忌、简注。穷通宝鉴无命例无推理，技能以口诀查阅为主。

**当 结构主干 = 混合型 时：取篇幅更大的方向。**

---

**取格判定逻辑的处理**：格局型书的取格逻辑收进每个格局技能的第一步（"先看月令是否正官..."），不单独出取格技能。断事型书的取格逻辑作为每个断事技能的前置章节。

**跨格局元规则的处理**：子平真诠型书常有"论用神""论行运""论格局变化"等独立章节，产出的规则不隶属于任一格局。这些元规则不单独出技能，而是抽取为**共享断法步骤**，写入该类型下每个格局技能的第一步（"断法步骤 > 通用前置：本书用神选取总则 / 行运喜忌总纲 / 格局转化通则"），作为该技能分析流程的前置段落。避免在每个技能正文中重复堆砌。

**通用断法技能**：通用断法章（论性情/论疾病/论大运/论太岁/纳音等）是跨格局的独立断法体系，拆散归入各格局技能会稀释。处置见上方"非格局 L4 节点处置"的第 0 级规则。核心原则：格局型书热度 🔥🔥 以上的通用断法必须出独立技能；断事型书通用断法按断事分组正常承载。

**薄节点的合并**：格局型书中，同一 L4 节点下若有多个同级子节点、平均每个 <5 条规则（如渊海子平外格下的飞天禄马/倒冲格/六乙鼠贵等各仅 2-5 条），合并为一个技能，内部按子节点分层。不拆成多个技能。

**格局型书中，一个格局出不出技能，看该格局在骨架热度表中的热度**：🔥🔥🔥 必出，🔥🔥 看候选质量，🔥 并入最近的同类型格局技能（如七杀格热度低时可并入正官格作为"官杀对比"章节），✗ 不单独出。

**断事型书中同理**：🔥🔥🔥 的断事领域必出技能，🔥🔥 看候选质量。

**格局型书中的断事聚合**：格局技能内部按骨架热度分深浅——热度 🔥🔥🔥 的断事维度写全规则集+命例，🔥 的维度只列核心规则，✗ 的维度一句带过（"本书在此格局下未专门论述健康"）。

**格局型书中非格局 L4 节点（如女命、六亲、诗诀等章节）的处置**：这些章节不是格局但骨架从目录中长出了独立 L4 节点。按以下优先级处理：
0. **通用断法章**（论性情/论疾病/论大运/论太岁/纳音/论六亲/论小儿）：这些是跨格局的独立断法体系，拆散归入各格局技能后，每条格局技能只能分到 1-2 条碎片，不成体系。处置：热度 🔥🔥 以上的通用断法章**出独立技能**（name 如 `<简称>-xingqing`、`<简称>-jibing`、`<简称>-dayun`、`<简称>-nayin`），不拆散归入格局。多条通用断法热度不足时可合并为一个技能（如 `<简称>-xingqing-jibing`）。
1. 若该节点内容是跨格局的（如诗诀或赋文涉及多个格局），规则拆散后归入对应格局技能，不单独占技能名额
2. 若该节点内容是对某一子人群的专论（如女命），内容折叠入最相关的格局技能作为子节（如女命章折入正官格/七杀格作为"本格女命专论"），不单独占名额
3. 只有在节点内容无法归入任何格局技能、且候选数量足够独立成章时，才考虑单独出技能（如渊海子平的神煞因其跨格局且量大，可合并入女命技能）
4. 核心原则：格局型书的名额优先给格局节点，🔥🔥🔥 格局必占，🔥🔥 格局力争；通用断法章适用第 0 级规则，不适用第 1 级的"拆散归入格局"

### 数量上限

按有效字数分档（同原版，但转写稿的目标和上限各减 2）：

| 有效字数 | 目标数量 | 硬上限 |
| --- | --- | --- |
| 5,000 到 20,000 | 1 到 3 | 3 |
| 20,000 到 60,000 | 3 到 5 | 5 |
| 60,000 到 150,000 | 4 到 7 | 7 |
| 超过 150,000 | 6 到 10 | 10 |

超出上限按一个标准排序截断：**这条能不能让一个拿到八字排盘的人，根据它做出一个具体判断。** 越具体、越可执行的排越前。

模型热度为 ✗ 的节点，即使有若干规则也不单独出技能。这些规则要么合并到最近的断事技能里做补充，要么降级为附录。

### 每个技能必须包含

1. **入口判定**（格局型/概念型书）：让技能拿到八字后能判断是否属于自己的管辖范围。格局型书是本格局的取格条件和边界；概念型书是"此概念在此八字中是否成立"的判断条件。
2. **断法步骤**：先看什么后看什么，每步标注模型路径。格局型书按"成格判断→用神选取→相神检查→行运配合→断事"；断事型书按"日主强弱→对应十神配置→冲合关系→大运应期"；概念型书按"概念判定→配套条件检查→关联命例→断事推论"；调候型书按"月令定位→日干定位→查表取口诀"。
3. **规则集**：按模型路径分层排列的规则表（每条含触发条件、结论、出处）。
4. **参考命例**：从命例库中选取与本技能相关的命例。调候型书若无命例则省略。
5. **失效场景**：什么八字配置下本技能的规则不适用。

### 技能间关系写入 description

如果技能之间有前置依赖（如"先判定格局再断婚姻"），必须在 description 中写明，不能只写正文。

### 构造方式

每个技能包可派一个子 Agent 并行构造。派发时必须传入以下全部信息：

1. 该技能对应的所有候选规则/命例
2. `骨架.md` 的"盲点与边界""书专属模型扩展""结构主干"全文
3. `references/skill-template.md` 完整内容
4. `references/bazi-model.md`（格局型书重点传 L4，概念型书传对应概念节点，调候型书传 L1+L3 调候维度，断事型书传 L8）
5. **【硬参数】本书内容简称**：从骨架.md 中取，如 `yaunhai`、`ziping`。子 Agent 构造的每个技能 name **必须以这个简称为前缀**（如 `yaunhai-zhengguan-ge`）。严禁使用泛域名前缀如 `mingli-`——蒸馏第二本书时会撞名

## 第 6 步 · 双层诱饵测试

### 测试前元信息闸门

逐个打开每个 `SKILL.md`，检查：

1. 第一行是不是三个减号
2. `name` 是否跟文件夹名完全一致
3. `name` 是不是小写拼音加连字符
4. `description` 长度是否在 60 到 120 字
5. 如果有前置技能依赖，description 里是否写了

任何一项不合格，立即补全。

### 盲测

按 `references/test-prompts-template.md` 造题并执行，产出 `技能包/测试题.md`。

命理版测试题的差异：
- 第一层（同源混淆）：测试题面使用用户日常询问八字的自然语言，例如"帮我看下这个八字婚姻怎么样""我这个八字什么时候能发财"
- 第二层（宿主混淆）：除了通用干扰题，加两道命理干扰题——"帮我用紫微斗数分析一下""帮我看一下手相"，正确答案是都不该触发（八字技能不应抢其他术数领域）

**必考题**：
> 帮我把这本命理书蒸馏成技能

正确答案是触发「命学真典」，不是任何新产出的八字分析技能。

答错就改对应技能的 description。重测全部题目，最多两轮。
